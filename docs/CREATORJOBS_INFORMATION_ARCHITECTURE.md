# CreatorJobs Website Information Architecture

Generated: 2026-05-17

Scope: static code inspection of the Next.js app router, frontend components, frontend API routes, `lib/backendClient.ts`, and FastAPI v1 routers. This document describes the information architecture currently represented in code, including reachable pages, visible controls, generated/repeated controls, empty/error states, API dependencies, placeholder actions, and dormant components/routes.

Flowchart reference: use `docs/CREATORJOBS_FLOWCHART_REFERENCE.md` for a page-by-page control map showing which buttons, links, tabs, cards, and form actions lead to which routes, modals, API actions, or placeholder states.

## 1. Product Shape

CreatorJobs is currently organized around five user-facing areas:

1. Public marketplace job discovery at `/`.
2. Authentication and onboarding intent flows under `/auth`.
3. Authenticated unified profile/dashboard at `/you`.
4. Job posting flow at `/post-job`.
5. Public acquisition/profile surfaces at `/jobs/[id]` and `/u/[slug]`.

Secondary or unfinished areas:

1. Applications pages under `/you/applications/*` are visible but mock-data backed.
2. Saved jobs redirects to `/you?tab=saved`, but the current `/you` UI renders only `overview`, `jobs`, and `portfolio` profile tabs.
3. Development/testing routes exist at `/dev/logo-debug` and `/smart-typing-test`.
4. Several local API routes and legacy profile components exist but are not currently used by the primary UI.

## 4. Public Job Feed `/`

Source: `app/page.tsx`, `components/JobGridClient.tsx`, `components/JobCard.tsx`, `components/jobs/ChannelAttribution.tsx`.

Data:

- If `NEXT_PUBLIC_USE_LOCAL_MOCKS` is true, jobs come from local repository data.
- Otherwise jobs come from backend `GET /jobs?limit=100&offset=0`.
- Query param `posted=1` displays a confirmation notice.

Page structure:

- Fixed category/filter chip bar below global header.
- Job grid with responsive columns.
- Empty state card when no jobs match current client-side filters.

Filter controls:

- Category chip buttons generated from `CATEGORIES`.
  - `All` shows all jobs.
  - Other category chips filter client-side by `job.category`.
- `Start within` button toggles visibility of start-time filter chips.
- Start-time chips generated from `START_TIME_VALUES`.
  - Each toggles inclusion in `selectedStarts`.

Job card controls:

- Entire card:
  - `role="link"`, keyboard accessible with Enter/Space.
  - Navigates to `/jobs/{id}`.
- Channel name button:
  - If normal poster and profile slug exists, navigates to `/u/{slug}`.
  - If no profile slug, disabled with `Profile not available`.
  - If agency-posted, opens chooser modal.
- Agency chooser modal:
  - Backdrop click closes.
  - Escape closes.
  - `X` closes.
  - `CreatorJobs profile` opens `/u/{slug}` when available, otherwise disabled.
  - `YouTube channel` opens `https://www.youtube.com` placeholder in a new tab.
- Save icon:
  - Stops card navigation.
  - Shows `alert("Saved: {TITLE}")`.
  - No persisted saved-job backend exists.
- Share icon:
  - Stops card navigation.
  - Copies job URL to clipboard.
  - Shows `alert("Link copied!")`.
- Stat tiles are displayed as interactive-looking rows but do not navigate.

Current gaps:

- Header search is not wired to the feed.
- Feed filters are client-side and do not persist to URL.
- Save is alert-only.

## 5. Authentication `/auth`

Source: `app/auth/page.tsx`, `components/AuthPage.tsx`, `lib/auth.ts`, backend `/auth/*`.

Modes:

- `mode=login` renders login form.
- `mode=signup` renders signup form.
- Mode buttons update the URL query.

Shared controls:

- `Log in` mode button.
- `Sign up` mode button.
- `Continue with YouTube` button:
  - Calls `signIn("google")`.
  - Callback route is `/auth/onboarding-intent` unless a safe `next` path is provided.
- `Back to jobs` link: `/`.

Login form:

- Email input.
- Password input.
- `Resend verification email` button:
  - Disabled if email is missing/invalid or resend is busy.
  - Calls backend `/auth/resend-verification`.
- `Log in` submit button:
  - Calls NextAuth credentials provider.
  - Credentials provider calls backend `/auth/login`.
  - Redirects to safe `next`, onboarding intent, or `/you`.

Signup form:

- Initial intent selector buttons:
  - `I am looking for work`.
  - `I am hiring creator talent`.
  - `I want to do both`.
  - `I will decide later`.
- Username input.
- Email input.
- Password input.
- Confirm password input.
- `Resend verification email` button with same validation as login.
- `Sign up` submit button:
  - Calls backend `/auth/register`.
  - Shows success or server error.
  - In development, may show `Open verification link` when backend returns a verification URL.

Validation/errors:

- Client validates email presence/shape, username/password basics, password confirmation, and intent.
- Backend handles duplicate email, duplicate username, invalid username, unverified login, and invalid credentials.

## 6. Email Verification `/auth/verify`

Source: `app/auth/verify/page.tsx`, `components/VerifyEmailPage.tsx`.

States:

- Success state offers `Go to log in`.
- Error state shows message, email input, and resend controls.

Controls:

- Email input for resend.
- `Resend verification email` button:
  - Calls backend `/auth/resend-verification`.
- `Go to log in` link/button:
  - Navigates to `/auth?mode=login`.

- `POST /auth/register`: email/password registration.
- `POST /auth/verify-email`: verify email token.
- `POST /auth/resend-verification`: generic resend verification response.
- `POST /auth/login`: email/password login.
- `POST /auth/oauth/google`: exchange Google OAuth identity for backend JWT.

Current user/profile:

- `GET /me`: current authenticated user plus profile capabilities.
- `PATCH /me/account-type`: deprecated compatibility endpoint mapped to onboarding intent.
- `PATCH /me/onboarding-intent`: update onboarding intent.
- `POST /me/oauth/google/upsert`: upsert Google OAuth tokens.
- `POST /me/youtube/refresh`: refresh linked YouTube channels.
- `GET /me/youtube/channels`: list verified YouTube channels.
- `GET /me/profile`: get profile settings.
- `PATCH /me/profile`: update profile settings.
- `PATCH /me/privacy`: update privacy settings.
- `GET /me/hiring-identities`: list hiring identities.
- `POST /me/hiring-identities`: create hiring identity.
- `PATCH /me/hiring-identities/{identity_id}`: update hiring identity.
- `POST /me/hiring-identities/{identity_id}/request-verification`: request verification.
- `GET /me/portfolio`: list current user's portfolio.
- `POST /me/portfolio`: create current user's portfolio item.
- `PATCH /me/portfolio/{item_id}`: update current user's portfolio item.
- `DELETE /me/portfolio/{item_id}`: delete current user's portfolio item.

Jobs:

- `GET /jobs`: list jobs with `q`, `platform`, `location`, `start_timeframe`, `status`, `limit`, and `offset`.
- `GET /jobs/{job_id}`: job details.
- `POST /jobs`: create job.
- `PATCH /jobs/{job_id}`: update job; requires owner/admin.
- `DELETE /jobs/{job_id}`: soft-delete/archive job; requires owner/admin.

Portfolio:

- `POST /portfolio/youtube/preview`: preview YouTube metadata.
- `POST /portfolio/youtube`: create portfolio item from YouTube.
- `GET /portfolio/items`: list portfolio proof items for `me` or a user id.
- `POST /portfolio/items`: create portfolio proof item.
- `PATCH /portfolio/items/{item_id}`: update portfolio proof item.
- `DELETE /portfolio/items/{item_id}`: delete portfolio proof item.
- `GET /portfolio/{user_id}`: list portfolio items by user id.

Roles and content style:

- `GET /roles`: list supported creator roles.
- `GET /roles/{role_id}/questions`: list role clarification questions.
- `GET /user/roles`: current user's roles.
- `POST /user/roles`: set current user's roles.
- `GET /user/role-answers`: current user's role answers.
- `POST /user/role-answers`: upsert role answers.
- `GET /user/content-style`: current user's content style.
- `POST /user/content-style`: upsert current user's content style.
- `GET /content-style/niches`: list supported niche values.
- `GET /profile/completion`: authenticated user's profile completion status.

Public users:

- `GET /users/{username}/public-profile`: public profile by username.
- `GET /users/{username}/jobs?tab=active|past`: public jobs by username.
- `GET /users/{username}/portfolio?tab=now|past`: public portfolio by username.

Health/dev:

- `GET /health`: liveness.
- `GET /health/db`: database connectivity.
- `POST /dev/seed/jobs`: development-only sample job seed.
- Backend root `/`: returns service/version.

## 18. Placeholder, Mock, Or Incomplete Interactions

Highest-impact placeholders:

- Job detail `Apply` is alert-only.
- Job detail `Save` is alert-only.
- Job card `Save` is alert-only.
- Saved jobs route does not resolve to a complete saved-jobs experience.
- Applications sent/received use mock data.
- Received applicant dashboard is not backed by real application records.
- Header search input and search button do not query or navigate.
- Header mic button has no action.
- Notification popover says `Notifications coming soon`.
- Post-job preview card save/share buttons are visual only.
- Agency `YouTube channel` chooser opens the generic YouTube homepage placeholder.
- Instagram verification in post-job form is not implemented.
- Root metadata still uses default Create Next App values.

Structural IA risks:

- `/you?tab=saved` is redirected to by `/you/saved`, but saved is not rendered in the current profile tab set.
- Public, owner, and application portfolio concepts are present, but applications are still mock-only.
- There are two profile tab component generations: active `YouHubClient`/`PublicProfileTabs` and dormant `ProfileTabs`.
- Local mock job creation and backend job creation coexist; behavior depends on env.
- Some server-side gates are intentionally deferred per launch-readiness doc, especially paid features and application permissions.

## 19. Recommended Team Review Checklist

Review these IA decisions with product/design before broad implementation:

- Whether saved jobs should live inside `/you` or as a separate `/you/saved` page.
- Whether applications should stay as separate routes or become a `/you` dashboard tab.
- Whether public profile tabs should mirror owner profile tabs exactly.
- Whether search should be global header search, feed-local search, or both.
- Whether job detail `Apply` should open a modal, route to an application page, or submit inline.
- Whether post-job should remain gated by Hiring Info before form entry or allow draft-first creation.
- Whether dev routes should remain public in non-development environments.
